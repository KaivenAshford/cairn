# 内容目录

```
entries/     ← 真实条目。**单独的 private 仓库**，被根 .gitignore 忽略
fixtures/    ← 几条示例，进代码仓。本地开发和测试用
```

## 为什么内容不进这个仓库

代码可以给人看，内容不一定。分成两个仓库之后：

- **四层可见度纯粹由 frontmatter 决定**，不再一半由字段、一半由「在哪个仓」决定。
  `unlisted` 曾经跟代码躺在同一个仓库里——它「猜不到文件名」的防护对任何能打开
  仓库的人都不生效，而这件事在目录结构里看不出来。
- **私密条目被提交进公开仓库**这条不可逆的路径直接消失。这是唯一一类「发生了就没法
  撤销」的泄露：git 历史改不掉，而 dist 重新构建一次就好了。
- 内容仍然有版本历史、仍然能本地用编辑器写、服务器炸了仍然不丢——这几条是当初
  坚持「markdown in git」的理由，换成私有内容仓之后一条都没丢。

## 第一次准备

```sh
git clone <你的私有内容仓> web/content/entries    # 生产
scripts/seed                                      # 或者本地开发：把 fixtures 复制进去
```

`entries/` 为空时站是空的，构建不会失败——`scripts/test-visibility` 会自己造条目来跑。
